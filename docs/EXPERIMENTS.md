# Правила экспериментов

1. Зафиксировать clean Git commit и не менять examples/ или JSONL между сравниваемыми
   прогонами.
2. Использовать Python 3.12, одинаковое оборудование и локальные модели. Записать
   точное имя/квантизацию Ollama и embedding-модели.
3. Менять одну независимую переменную: retrieval-стратегию, top-k, prompt или
   generation setting. Не смешивать изменения алгоритма и датасета.
4. Запускать полный набор последовательно. Не исключать неудачные сценарии из
   агрегатов; ошибки и неопределённые оценки должны оставаться в артефактах.
5. Сравнивать только одинаковые dataset SHA-256 и corpus SHA-256. Случайные UUID
   документов не являются идентичностью корпуса.
6. Retrieval-метрики интерпретировать отдельно от generation. Валидная [N] означает
   только существование номера, а не поддержку утверждения источником.
7. Выполнить ручную проверку всех manual_review_required, особенно конфликтов,
   полноты multi-document ответа и обоснованности отказа. Записать reviewer и дату.
8. Не использовать оцениваемую модель для создания эталонных фактов. LLM Judge в
   CLIP-003 запрещён.
9. Не коммитить .env, runtime, результаты с конфиденциальными вопросами или пароли.

## Минимальная запись изменения

В отчёте указываются гипотеза, commit SHA, ID прогонов, изменённый параметр,
retrieval/latency/token deltas, число ошибок, ручная проверка и вывод. Улучшение одной
средней метрики без анализа регрессий по сценариям не доказывает улучшение.

## Стратегии

Reranking в CLIP-005 сохраняет format_version=clip-evaluation-run/v1, тот же блок
dataset, corpus hash, retrieved_documents и полный retrieval trace. MultiQuery, если
будет реализован отдельно, должен соблюдать тот же контракт и сравниваться тем же CLI.
