# CLIP-012 — Strict Agent

## Назначение и границы

CLIP-012 делает AI-Агент режимом по умолчанию для новых конфигураций и переводит
публикацию ответа в fail-closed режим: при недостаточных доказательствах, некорректном
ответе модели или техническом сбое корпоративное утверждение не выдаётся как
подтверждённое. Внутренние API-значения `agent` и `baseline` сохранены. Многотуровый
диалог, создание обращения и экспертное пополнение базы знаний не добавлены.

Существующий `.env` не изменяется автоматически. Если в нём явно записано
`AGENT_ENABLED=false`, стенд продолжит использовать Базовый RAG до ручного изменения
владельцем и согласованного перезапуска backend.

## Входная проверка

`backend/clip_agent/guardrails.py` выполняется до retrieval и LLM:

1. отклоняет пустой ввод, одни знаки, повторяющиеся случайные символы и текст без
   достаточного русскоязычного компонента;
2. принимает короткие русские вопросы и смешанный русский текст с SS, АМ, РМ, РП,
   ПА, CRM, SLA, RFI, SharePoint и Wiki;
3. детерминированно отклоняет типовые запросы к написанию кода, творчеству, погоде и
   новостям, если они не сформулированы как вопрос по корпоративному документу;
4. обнаруживает сочетания смены роли, обхода проверки, раскрытия system prompt и
   подмены источников. Обсуждение или цитирование такой фразы с явным исследовательским
   намерением не блокируется автоматически.

Результат входной проверки сохраняется в trace как `outcome` и безопасный
`reason_code`; retrieval при отклонении не запускается. Это эвристическая защита, а не
доказательство абсолютной безопасности. Возможны ложные отказы и пропуски новых форм
атаки.

## Недоверенные документы

Исходный текст остаётся неизменным в PostgreSQL и в карточке источника. Перед передачей
LLM instruction-like предложения удаляются только из model context и заменяются
нейтральным маркером. Prompt отдельно объявляет блоки источников недоверенными данными и
запрещает менять роль, правила, вызывать инструменты или инициировать внешние действия.
Флаг `document_security_flags` сопровождает выбранный evidence в runtime/API. Агент не имеет
инструментов выполнения команд или отправки сообщений.

Фильтр намеренно консервативен: легитимный регламент, описывающий команды или prompt
injection, может потребовать ручного просмотра. Полная семантическая изоляция недоверенных
данных остаётся ограничением прототипа.

## Строгая проверка ответа

Конвейер AI-Агента:

```text
input guard
  -> bounded retrieval
  -> evidence assessment per aspect
  -> optional targeted retrieval
  -> deterministic ambiguity/conflict gates
  -> composition
  -> citation validation/repair
  -> semantic grounding validator
  -> outcome + SearchTrace
```

Изменения fail-closed:

- malformed или недоступный evidence assessor больше не объявляет первый фрагмент
  достаточным;
- незакрытый evidence gap после исчерпания search/retry budget приводит к
  `quality_review_required`;
- каждый публикуемый ответ, а не только заранее отмеченный «рискованный» вопрос,
  проходит semantic grounding validator;
- validator проверяет существенные утверждения, область действия, отрицательные выводы,
  приоритет документов и соответствие факта его цитате;
- `valid` обязан быть JSON boolean; malformed JSON, отсутствие LLM или исчерпание
  необходимого LLM budget дают контролируемый `technical_error`;
- неправильные citation IDs после bounded repair заменяют draft безопасным исходом;
- temporal guards CLIP-004 сохранены;
- Базовый RAG остаётся отдельным режимом, но также проходит citation gate и semantic
  grounding validator. Неподтверждённый baseline draft не публикуется.

LLM validator является дополнительным локальным барьером, а не независимым источником
истины. Текущий прототип не доказывает полное отсутствие галлюцинаций; содержательная
проверка на реальном корпусе требует эксперта и versioned evaluation dataset.

## Семантика outcome

Ответ `/api/v1/ask` сохраняет `answer`, `sources`, `retrieval`, `trace_id`, `metrics` и
добавляет `outcome`, `reason_code`:

| Outcome | Значение |
|---|---|
| `answered` | draft прошёл citation и grounding validation |
| `clarification_required` | минимум два найденных источника подтверждают разные области, а вопрос не содержит решающего условия |
| `quality_review_required` | регламентов или evidence недостаточно либо вывод не подтверждён |
| `conflict_detected` | минимум два найденных источника содержат несовместимые положения; приоритет не выбран |
| `out_of_scope` | запрос не относится к корпоративным документам |
| `invalid_input` | невалидный язык/форма или instruction attack |
| `technical_error` | runtime/LLM/JSON/budget не позволил безопасно завершить проверку |

`SearchTrace.status` остаётся техническим полем. `status=ok` не является знаком
содержательной корректности. `outcome` и `reason_code` записываются в
`SearchTrace.details`; сырые исключения хранятся для диагностики, но редактируются в
клиентской проекции.

## Неоднозначность, отсутствие данных и противоречия

Уточняющий вопрос принимается только из structured assessment при наличии как минимум
двух реальных `source_id`. Он не сохраняется как состояние диалога: продолжение будет в
CLIP-014.

Если источников нет, остаётся evidence gap или итоговый вывод не подтверждён, ответ
предлагает обратиться в службу качества. Обращение не создаётся. Это CLIP-015.

Конфликт принимается только при двух разных найденных `source_id`. Ответ перечисляет
подтверждённое противоречие, показывает цитаты, не определяет приоритет и предлагает
эскалацию.

## Отказ LLM и запрет fallback

Исключение `run_agent()` теперь завершает исходом `technical_error`. Базовый RAG
автоматически не запускается, `fallback_attempted=false` сохраняется в trace. Пользователь
получает безопасное сообщение без exception text. Явный `baseline` через существующий
demo override по-прежнему доступен.

## Интерфейс

UI использует названия «AI-Агент» и «Базовый RAG», но отправляет прежние значения
`agent`/`baseline`. До успешного ответа `/api/v1/capabilities` режим не предполагается:
форма показывает загрузку фактической backend-конфигурации. Outcome отображается
отдельным статусом. Ссылки на источники остаются кликабельными; UI прямо не называет
автоматический ответ экспертно утверждённым.

## Тестирование

Профильный прогон CLIP-012: `40 passed`, две существующие FastAPI `on_event`
deprecation warnings. Тесты используют scripted/mocked LLM и deterministic retrieval.
Они покрывают русский текст с сокращениями, invalid/out-of-scope, input и document
injection, ambiguity, conflict, отсутствие evidence, неверные citations, unsupported
scope, malformed JSON, runtime exception без fallback и strict baseline validation.

Реальный Ollama и живые PostgreSQL/Qdrant/OpenSearch в CLIP-012 не вызываются: это
исключает изменение действующего стенда и пользовательских traces. Результаты полного
прогона на итоговом рабочем дереве:

- полный pytest: `77 passed`, две существующие FastAPI deprecation warnings;
- Ruff: `All checks passed`;
- pip check: `No broken requirements found`;
- TypeScript project check: passed;
- Vite production build: passed, 29 modules;
- `git diff --check`: passed, только информационные LF/CRLF warnings;
- `npm audit --omit=dev`: не запускался, потому что npm CLI отсутствует в доступной
  среде; зависимости frontend в CLIP-012 не изменялись.

## Ограничения

- эвристики языка, осмысленности, scope и injection допускают false positive/negative;
- ambiguity/conflict classification зависит от локальной LLM, но код проверяет реальные
  source IDs и fail-closed обрабатывает malformed output;
- semantic validator снижает риск, но не является формальным entailment prover;
- нет ACL, OCR, гарантированного разбора таблиц, экспертного approval и многотурового
  состояния;
- текущие тесты синтетические и mocked; качество на документах заказчика не измерено.

## Безопасное применение к публичному стенду

Автоматическое применение в CLIP-012 запрещено и не выполнялось. После отдельного
разрешения владельца:

1. проверить `git status`, SHA, фактические PID/командные строки FastAPI и Caddy,
   состояние Funnel и read-only `/healthz`/`/readyz`;
2. сохранить текущий `.env` вне Git и не выводить секреты;
3. выполнить финальные проверки из этого документа на том же SHA;
4. вручную изменить в существующем `.env` только `AGENT_ENABLED=true`, если AI-Агент
   должен стать default; `AGENT_DEMO_OVERRIDE_ENABLED` оставить согласно политике стенда;
5. собрать frontend во временном/подготовительном контуре и проверить, что bundle
   соответствует тому же SHA; не заменять работающий bundle до окна обновления;
6. в согласованное окно перезапустить только FastAPI штатным способом владельца, затем
   атомарно заменить frontend bundle; Caddy и Funnel не менять, если их конфигурация не
   менялась;
7. выполнить read-only capabilities/health/readiness и один разрешённый синтетический
   запрос; убедиться, что default=`agent`, outcome отображается и trace не содержит
   baseline fallback;
8. при ошибке вернуть прежний bundle и прежнее значение `.env`, затем перезапустить
   только FastAPI. Документы, индексы и базы не очищать.
